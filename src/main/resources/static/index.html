How this works :- naive vs. atomic

✕ naive implementation

Checking token availability and decrementing happen as two separate steps. When requests overlap in timing, multiple clients can read the same count before either finishes updating it — so more requests get through than the bucket actually has room for.

✓ atomic fix

The check and decrement happen as one step inside a single Redis Lua script. Redis runs it start-to-finish with nothing allowed to interleave — so no two requests ever read the same stale count, even across multiple app instances.
